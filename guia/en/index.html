What it is

One interface, with the seams visible

Most creative AI products combine five useful pieces — model access, prompt refinement, routing, storage, and billing — and hide the seams behind a monthly subscription. Bench keeps the convenience and makes every seam inspectable.

🔑 Your keys are yours

They stay on your machine's server and never go to the browser. A provider without a key appears as unavailable, with the reason and how to fix it — the studio starts up anyway.

🎚️ Schema-driven controls

Each model shows what it actually accepts: how many reference images, whether it supports a first and last frame, and which durations and resolutions are available. No generic upload box.

💸 Cost in real units

Estimate before running and recorded spend afterward. When the unit is unpredictable, it says so instead of making up a total — and actual usage is measured against the account balance.

How it works

From idea to file in your folder

The same workflow applies through the interface and MCP — what an agent client (Claude Code, Codex, Cursor) does is enter through another door to the same engine.

idea→ prompt refinement→ model selection→ budget→ generation→ local mirror→ cash ledger

✍️ Editable prompt

The draft is rewritten for the selected model and remains visible before you spend. You approve, edit, or discard it—nothing is sent behind your back.

🗂️ Local custody

Every output is mirrored in data/outputs. Provider URLs expire; your files don't.

🔌 MCP on the same engine

npm run mcp exposes the catalog and generation to compatible clients, with the same cost and custody rules.

Prerequisites

Node and a key — everything else is optional

Every provider fails gracefully: a missing key won’t bring down the studio; it only marks those models as unavailable. Set up at least one to generate something.

Node 22.5+

Node 24 recommended — Bench uses node:sqlite. More npm, and nothing else.

# check the version
node --version

fal.ai · 37 models

Charges in dollars, with live pricing per endpoint.

# .env
FAL_KEY=sua-chave

Kling · 26 models

Uses credits from your plan. Authenticates through OAuth in the official CLI, not with a key.

npm i -g @klingai/cli-global
kling login

Agnes AI · 4 models

Free generation. Requires an English prompt — that's why the refiner matters.

# .env
AGNES_API_KEY=sua-chave

kie.ai · 4 models

Charges in credits. No API for per-model pricing: the estimate is offline and labeled as estimated.

# .env
KIE_API_KEY=sua-chave

Prompt refiner

Optional, but recommended: without it, the prompt goes in raw. Google AI Studio or OpenRouter.

# .env — either one
GOOGLE_API_KEY=sua-chave
OPENROUTER_API_KEY=sua-chave
User guide · step by step

From zero to your first generated file

Real commands from the repository. You can go from cloning to generating in three minutes.

1

Clone and install

Just one system dependency: Node.

git clone https://github.com/inematds/bench-studio-br.git
cd bench-studio-br
npm install
2

Add your credentials

O .env.example documents all 16 variables: what each one enables, how it charges, and where to create the key. Fill in only what you have. Read them in this order: exported in the shell > .env of the project > ~/.env.

cp .env.example .env  # then edit whatever you have
3

Start the studio

The server and UI start together. The UI is available at http://localhost:5200 and the API, on loopback, at port 8787.

npm run dev  # http://localhost:5200
4

Or configure it through the UI without touching a file

The button Config shows every setting — whether it’s present or missing, where the value came from, and the last 4 characters — tests each provider, and writes the .env for you. For security, it only accepts writes from the same machine; over the network, it’s read-only.

# the key value never appears on screen, only the last 4 characters
5

Choose a model based on what it accepts

In the selector, filter by output (image or video) and provider, and search by name — all three criteria combine. Each model lists its reference capability: 1 image, up to 10 images or opening + closing frame.

# 10 models accept a first and last frame; they get two
# numbered selectors, ① opens and ② closes the video
6

See the price before you spend

The bar shows the estimate when it can be calculated (10 segundos × $0,14). When the unit doesn't let you predict the quantity, it shows the unit price and says the exact amount will be available after generation — instead of displaying an invented total.

# after running, the actual cost is recorded in the ledger
7

Secure it if you’re leaving the machine

The studio starts up without a password, intentionally. Before making it accessible over the network, set one — and it can only be set from the machine itself, which prevents a stranger from locking the owner out.

npm run set-password            # set or change it; it takes effect immediately
npm run set-password -- --remove  # removes

To reach the studio from another machine, follow this entire sequence—from top to bottom:

npm run set-password                        # 1. password BEFORE opening the door
./scripts/remote.sh open                    # 2. publish the interface + firewall rule
# 3. restart the studio the way you keep it running
./scripts/remote.sh status                  # 4. check: accessible where, with what protection
# ...use...
./scripts/remote.sh close                   # 5. when you're done
# 6. restart again to bring down the open socket

Restarts aren’t just ceremony: the open e o close write to the .env, and the process reads at startup which interface to listen on. Without restarting, the file says one thing and the running socket does another — and it's the status that tells you this. The open still asks for the password before opening anything, and never exposes the API: port 8787 stays on loopback.

8

Use it through an agent via MCP

The same catalog and generation, available to Claude Code, Codex, Cursor, and other compatible clients.

npm run mcp       # MCP server
npm run test:mcp  # quick contract check
9

Keep the catalog up to date

fal's lineup is discovered from the live catalog; Kling's comes from its own CLI. You can sync it manually or leave it on automatic (the selector auto is on the catalog title line).

npm run catalog:sync   # discover new endpoints
npm run registry       # rebuilds the registry
npm run capabilities   # rebuilds the input manifest
10

Update an existing installation

Run the four commands below, in this order. They apply no matter how you start the studio — you don’t need to know which mode you’re in.

cd bench-studio-br
git pull
npm install      # does nothing when nothing has changed
npm run build    # harmless in practice if you never serve the dist/

Then restart the same way you started it. The project doesn't install any services: systemctl restart bench-studio only works if you created this unit yourself (the README includes the ready-made template). If you set it up manually: pkill -f 'server/server.mjs' e npm run dev again.

Why the npm run build is on the list even though most use npm run dev: o dist/ isn’t versioned, so the git pull never updates a site that’s already being served. Building when it isn’t needed takes three seconds and leaves an unused folder; no building when needed leaves the screen frozen on the old version while the server updates underneath—which looks like a bug but isn’t. Always building is the cheapest mistake.

One detail that can trip up an old installation: the API now listens on loopback by default (BENCH_API_HOST). Before, it listened on all interfaces, so publishing the interface also exposed port 8787 — the one that writes files and spends money. A proxy on the same machine pointing to 127.0.0.1:8787 stays the same; anyone connecting to 8787 from another machine needs the explicit opt-out BENCH_API_HOST=0.0.0.0.
