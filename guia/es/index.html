Qué es

Una sola interfaz, con las costuras a la vista

La mayoría de los productos creativos de IA reúne cinco piezas útiles — acceso a modelos, refino de prompts, enrutamiento, almacenamiento y facturación — y oculta las uniones detrás de una mensualidad. Bench mantiene la comodidad y permite inspeccionar cada unión.

🔑 Las claves son tuyas

Se guardan en el servidor de tu máquina; nunca llegan al navegador. Los proveedores sin clave aparecen como no disponibles, con el motivo y cómo resolverlo: el estudio se inicia de todos modos.

🎚️ Controles que vienen del schema

Cada modelo muestra lo que realmente acepta: cuántas imágenes de referencia, si tiene cuadro inicial y final, y qué duraciones y resoluciones están disponibles. Nada de cuadros de carga genéricos.

💸 Costo en unidad real

Estimación antes de ejecutar y gasto registrado después. Cuando la unidad no es predecible, lo indica en vez de inventar un total; el consumo real se mide con el saldo de la cuenta.

Cómo funciona

De la idea al archivo en tu carpeta

El mismo flujo funciona desde la interfaz y desde MCP: lo que hace un cliente de agente (Claude Code, Codex, Cursor) es entrar por otra puerta al mismo motor.

idea→ refinamiento del prompt→ elección del modelo→ presupuesto→ generación→ espejo local→ libro de caja

✍️ Prompt editable

El borrador se reescribe para el modelo elegido y queda visible antes de gastar. Lo apruebas, editas o descartas: nada se envía a tus espaldas.

🗂️ Custodia local

Toda salida se refleja en data/outputs. Las URL de los proveedores vencen; tus archivos no.

🔌 MCP en el mismo motor

npm run mcp expone el catálogo y la generación a clientes compatibles, con las mismas reglas de costos y custodia.

Requisitos previos

Node y una clave; lo demás es opcional

Todos los proveedores fallan por su cuenta: si falta una clave, el estudio no se cae; solo marca esos modelos como no disponibles. Configura al menos uno para generar algo.

Node 22.5+

Node 24 recomendado — Bench usa node:sqlite. Más npm, y nada más.

# comprueba la versión
node --version

fal.ai · 37 modelos

Cobra en dólares, con precios en vivo por endpoint.

# .env
FAL_KEY=sua-chave

Kling · 26 modelos

Consume créditos del plan. Se autentica por OAuth en el CLI oficial, no con una clave.

npm i -g @klingai/cli-global
kling login

Agnes AI · 4 modelos

Generación sin costo. Requiere un prompt en inglés; por eso el refinador es importante.

# .env
AGNES_API_KEY=sua-chave

kie.ai · 4 modelos

Cobra en créditos. Sin API de precios por modelo: la estimación es offline y está identificada como estimada.

# .env
KIE_API_KEY=sua-chave

Refinador de prompts

Opcional, pero vale la pena: sin esto, el prompt va tal cual. Google AI Studio u OpenRouter.

# .env — cualquiera de los dos
GOOGLE_API_KEY=sua-chave
OPENROUTER_API_KEY=sua-chave
Guía de uso · paso a paso

De cero al primer archivo generado

Comandos reales del repositorio. Desde clonar hasta generar, puedes hacerlo en tres minutos.

1

Clonar e instalar

Una sola dependencia del sistema: Node.

git clone https://github.com/inematds/bench-studio-br.git
cd bench-studio-br
npm install
2

Agregar las credenciales

O .env.example documenta las 16 variables: qué habilita cada una, cuánto cuesta y dónde crear la clave. Completa solo lo que tengas. El orden de lectura es: exportado en el shell > .env del proyecto > ~/.env.

cp .env.example .env  # luego edita lo que tengas
3

Iniciar el estudio

El servidor y la interfaz se inician juntos. La interfaz queda en http://localhost:5200 y la API, en loopback, en el puerto 8787.

npm run dev  # http://localhost:5200
4

O configúralo desde la pantalla, sin tocar ningún archivo

El botón Config muestra cada ajuste — presente o faltante, de dónde vino el valor y los 4 últimos caracteres —, prueba cada proveedor y escribe el .env para ti. Por seguridad, solo acepta escrituras desde la propia máquina: por la red es de solo lectura.

# el valor de la clave nunca aparece en pantalla, solo los últimos 4 caracteres
5

Elegir el modelo según lo que acepta

En el selector, filtra por salida (imagen o video) y por proveedor, y busca por nombre: los tres criterios se combinan. Cada modelo indica qué tipo de referencia acepta: 1 imagen, hasta 10 imágenes o cuadro inicial + final.

# 10 modelos aceptan el primer y el último cuadro; obtienen dos
# selectores numerados, ① abre y ② cierra el video
6

Ver el precio antes de gastar

La barra muestra la estimación cuando se puede calcular (10 segundos × $0,14). Cuando la unidad no permite prever la cantidad, muestra el precio unitario y dice que el valor exacto se conocerá después de la generación, en lugar de mostrar un total inventado.

# después de ejecutarlo, el gasto real queda registrado en el libro de cuentas
7

Proteger, si vas a salir de la máquina

El estudio se inicia sin contraseña, a propósito. Antes de dejarlo accesible desde la red, define una — y solo se puede definir desde la propia máquina, lo que impide que un desconocido deje al dueño fuera.

npm run set-password            # define o cambia; se aplica de inmediato
npm run set-password -- --remove  # elimina

Para acceder al estudio desde otra máquina, esta es toda la secuencia, de arriba hacia abajo:

npm run set-password                        # 1. contraseña ANTES de abrir el puerto
./scripts/remote.sh open                    # 2. publica la interfaz + la regla del firewall
# 3. reinicia el estudio, de la forma en que lo mantienes en línea
./scripts/remote.sh status                  # 4. comprueba: qué está abierto y con qué protección
# ...usa...
./scripts/remote.sh close                   # 5. al terminar
# 6. reinicia de nuevo para cerrar el socket abierto

Los reinicios no son un trámite: el open e o close escriben en el .env, y el proceso lee al iniciarse en qué interfaz va a escuchar. Sin reiniciar, el archivo dice una cosa y el socket en ejecución hace otra — y eso es status que te lo cuenta. El open todavía solicita la contraseña antes de abrir cualquier cosa y nunca publica la API: el puerto 8787 queda en loopback.

8

Usar por medio del agente, vía MCP

El mismo catálogo y la misma generación, disponibles para Claude Code, Codex, Cursor y otros clientes compatibles.

npm run mcp       # servidor MCP
npm run test:mcp  # comprobación rápida del contrato
9

Mantener el catálogo actualizado

El catálogo activo permite descubrir los modelos de fal; los de Kling se obtienen del propio CLI. Puedes sincronizarlo manualmente o dejarlo en automático (el selector auto queda en la línea del título del catálogo).

npm run catalog:sync   # descubre endpoints nuevos
npm run registry       # reconstruye el registro
npm run capabilities   # reconstruye el manifiesto de entradas
10

Actualizar una instalación existente

Ejecuta los cuatro comandos de abajo, en este orden. Son válidos sin importar cómo inicies el estudio — no necesitas saber en qué modo estás.

cd bench-studio-br
git pull
npm install      # no hace nada cuando nada cambió
npm run build    # en la práctica, es inofensivo si nunca sirves el dist/

Después, reinicia de la misma forma que lo iniciaste. El proyecto no instala ningún servicio: systemctl restart bench-studio solo funciona si tú mismo creaste esa unit (el README trae el modelo listo). Si lo iniciaste manualmente: pkill -f 'server/server.mjs' e npm run dev de nuevo.

Por qué el npm run build está en la lista aunque la mayoría use npm run dev: o dist/ no se versiona, así que el git pull nunca actualiza un sitio servido ya listo. Hacer el build sin necesidad cuesta tres segundos y deja una carpeta sin uso; no Hacer el build cuando hacía falta deja la pantalla congelada en la versión antigua mientras el servidor se actualiza por debajo, lo que parece un error, pero no lo es. Hacer el build siempre es el error menos costoso.

Un detalle que afecta a las instalaciones antiguas: ahora la API escucha en loopback de forma predeterminada (BENCH_API_HOST). Antes se iniciaba en todas las interfaces, así que publicar la interfaz también publicaba el puerto 8787, el que escribe archivos y gasta dinero. Un proxy en la misma máquina que apunta a 127.0.0.1:8787 sigue igual; quien se comunicaba con la 8787 desde otra máquina necesita la opción consciente para desactivarlo BENCH_API_HOST=0.0.0.0.
